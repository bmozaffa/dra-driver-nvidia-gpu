install.md ---\n---\ntitle: Install the driver\nlinkTitle: Install\nweight: 40\ndescription: Helm install steps for the DRA driver.\n---\n\nInstall the DRA Driver for NVIDIA GPUs and validate that GPU or ComputeDomain allocation is working on your cluster.\n\nBefore you begin:\n\n- Confirm all [prerequisites](prerequisites.md) are met.\n- If you have the NVIDIA GPU Operator installed, follow the [GPU Operator install guide](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/latest/dra-intro-install.html) instead.\n\n---\n\n## Install the chart\n\nThe following command installs the DRA Driver with both GPU allocation and ComputeDomain support enabled.\n\nBy default, both resource plugins are enabled. If you only need one, the other can be left enabled with no impact on the cluster, or you can disable it explicitly:\n\n- To disable ComputeDomain support, add `--set resources.computeDomains.enabled=false`.\n- To disable GPU allocation, add `--set resources.gpus.enabled=false`.\n\n{{% alert title=\"Note\" %}}\nOn GKE, include `--set nvidiaDriverRoot=/home/kubernetes/bin/nvidia` so the driver uses the default NVIDIA driver install path on GKE.\n{{% /alert %}}\n\n```bash\nhelm install dra-driver-nvidia-gpu oci://registry.k8s.io/dra-driver-nvidia/charts/dra-driver-nvidia-gpu \\\n    --version {{< param \"driver_version\" >}} \\\n    --create-namespace \\\n    --namespace dra-driver-nvidia-gpu \\\n    --set gpuResourcesEnabledOverride=true\n```\n\nExample output:\n\n```\nNAME: dra-driver-nvidia-gpu\nLAST DEPLOYED: Wed Apr 29 02:21:24 2026\nNAMESPACE: dra-driver-nvidia-gpu\nSTATUS: deployed\nREVISION: 1\nDESCRIPTION: Install complete\nTEST SUITE: None\n```\n\nFor additional configuration options, see [Optional: Configure Helm values](#optional-configure-helm-values).\n\n## Verify installation\n\nAfter install, confirm all components are running and the expected DeviceClasses are registered.\n\n1. Check that all pods are `Running` and `Ready`:\n\n```bash\nkubectl get pod -n dra-driver-nvidia-gpu\n```\n\nExample output (with GPU allocation and ComputeDomains enabled):\n\n```\nNAME                                                READY   STATUS    RESTARTS   AGE\ndra-driver-nvidia-gpu-controller-7fb7956988-4kv59  1/1     Running   0          1m\ndra-driver-nvidia-gpu-kubelet-plugin-5qhc7         2/2     Running   0          1m\n```\n\nThe `controller` pod runs the ComputeDomain controller (1 container). The `kubelet-plugin` pod runs two containers, one for GPU resources (`gpus`) and one for ComputeDomain resources (`compute-domains`), so it shows `2/2` when both are enabled. One `kubelet-plugin` pod appears per GPU node.\n\nIf you installed with `--set resources.computeDomains.enabled=false`, the `controller` pod will not be present and the `kubelet-plugin` pod will show `1/1`. The same is true if you disabled GPU allocation during install.\n\n2. Confirm the DeviceClasses were registered:\n\n```bash\nkubectl get deviceclass\n```\n\nExample output:\n\n```\nNAME                                      AGE\ncompute-domain-daemon.nvidia.com           1m\ncompute-domain-default-channel.nvidia.com  1m\ngpu.nvidia.com                             1m\nmig.nvidia.com                             1m\nvfio.gpu.nvidia.com                        1m\n```\n\n`gpu.nvidia.com` is used for standard GPU allocation. `mig.nvidia.com` and `vfio.gpu.nvidia.com` are registered but only usable with the appropriate hardware and configuration. The `compute-domain-*` classes are used by the ComputeDomain controller.\n\nIf you installed with only ComputeDomain support, `gpu.nvidia.com`, `mig.nvidia.com`, `vfio.gpu.nvidia.com` will not be installed.\n\nIf you installed with only GPU allocation support, `compute-domain-daemon.nvidia.com`, `compute-domain-default-channel.nvidia.com` will not be installed.\n\n3. Confirm GPU nodes have advertised their ResourceSlices:\n\n```bash\nkubectl get resourceslice -o wide\n```\n\nExample output:\n\n```\nNAME                                              NODE          DRIVER                      POOL          AGE\n00-gpu.nvidia.com-worker-gpu-01-kx9f2             worker-gpu-01 gpu.nvidia.com              worker-gpu-01 3m\n00-compute-domain.nvidia.com-worker-gpu-01-ab3d7  worker-gpu-01 compute-domain.nvidia.com   worker-gpu-01 3m\n```\n\nThe ResourceSlice name is auto-generated from the driver name, node name, and a random suffix.\nThe pool name matches the node name, since each node gets its own pool.\n\nWhen GPU allocation support is enabled, each GPU node should appear with `gpu.nvidia.com` slices listing its available devices.\n\nWhen ComputeDomain support is enabled, each GPU node should also appear with `compute-domain.nvidia.com` slices listing\nits available IMEX daemon and channel devices.\n\nIf no slices appear, the kubelet plugin is not communicating with the API server.\nCheck that the driver pods are running and your GPUs are in a healthy state.\n\n```bash\nkubectl logs dra-driver-nvidia-gpu-kubelet-plugin-<hash> -n dra-driver-nvidia-gpu\n```\n\nFor additional help, consider filing an [issue in the DRA Driver repository](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/issues).\n\n## Optional: Configure Helm values\n\nThe following parameters are most commonly set at install time.\n\n| Parameter | Default | Description |\n|---|---|---|\n| `nvidiaDriverRoot` | `/` | Path to the GPU driver root on the host. The `IMEXDaemonsWithDNSNames` feature gate is enabled by default and requires this driver version. The ComputeDomain plugin will fail to start on older drivers unless `IMEXDaemonsWithDNSNames` is explicitly disabled.\n- Multi-Node NVLink (MNNVL) hardware. Nodes must be connected via NVLink fabric, such as GB200 NVL72 and similar systems.\n- A component that manages the `nvidia.com/gpu.clique` node label.\n  Use GPU Feature Discovery (GFD), or set `kubeletPlugin.containers.computeDomains.gpuCliqueLabelEnabled=true` so the ComputeDomain kubelet plugin manages the label.\n\n\n### Driver-managed IMEX\n\nThe default `resources.computeDomains.imex.mode=driverManaged` setting makes the DRA Driver create one `nvidia-imex` DaemonSet for each `ComputeDomain`.\nOn all GPU nodes where the `nvidia-imex-*` packages are installed, disable the host `nvidia-imex.service` systemd unit:\n\n```bash\nsystemctl disable --now nvidia-imex.service && systemctl mask nvidia-imex.service\n```\n\n### Host-managed IMEX\n\nBy default the driver owns the `nvidia-imex` daemon lifecycle, per the requirement above. For clusters where the operator already runs `nvidia-imex` as a host service (for example through systemd), set `resources.computeDomains.imex.mode=hostManaged` to stop the driver from creating per-ComputeDomain `nvidia-imex` DaemonSets. This **inverts** the requirement above: `nvidia-imex.service` must be installed, configured, and left **running** on every participating GPU node. Also, the `nvidia-imex` service should be configured with\n`IMEX_CMD_ENABLED=1` and `IMEX_CMD_UNIX_DOMAIN_PATH=/etc/nvidia-imex/imex_ctrl.sock` (configurable via Helm).\n\n{{% alert color=\"warning\" title=\"Warning\" %}}\nSome `nvidia-imex.service` units use `ProtectSystem=full`, which prevents the service from creating the default socket under `/etc`.\nFor these units, set `IMEX_CMD_UNIX_DOMAIN_PATH` and `resources.computeDomains.imex.hostSocketPath` to the same writable runtime path, such as `/var/run/nvidia-imex-ctrl.sock`.\n{{% /alert %}}\n\nHost-managed mode requires two Helm values together:\n\n```bash\n--set featureGates.HostManagedIMEXDaemon=true \\\n--set resources.computeDomains.imex.mode=hostManaged\n```\n\n- `featureGates.HostManagedIMEXDaemon` is an alpha gate that only unlocks setting `imex.mode=hostManaged`. It does not by itself change any behavior. Setting `imex.mode=hostManaged` without this gate enabled is a startup validation error (`helm install`/`helm template` fails immediately, and if bypassed, the controller and kubelet plugin pods will fail to start).\n- `imex.isolation` selects the IMEX isolation strategy, and applies under both `driverManaged` and `hostManaged` mode. It must be set to one of:\n  - `domain` (default) — all workloads running in the same IMEX domain share the same channel (0). Under `driverManaged` mode this is inherent to the model (the driver creates one `nvidia-imex` daemon per ComputeDomain); under `hostManaged` mode, multiple ComputeDomains can still run against the same host IMEX domain, all receiving channel 0, with no isolation between them.\n  - `channel` — intended to eventually give each workload a unique channel within an IMEX domain. Not implemented yet: setting it is a startup validation error regardless of `imex.mode`.\n  - Any other value is a startup validation error.\n- Changing `imex.mode` or `imex.isolation` on a cluster with active ComputeDomain workloads is not supported and is not enforced by the driver, drain and remove existing ComputeDomains first.\n\n#### Host IMEX readiness check (Unix domain socket required)\n\nBecause there is no driver-managed daemon to report readiness under host-managed IMEX, the kubelet plugin validates the host `nvidia-imex` daemon itself at channel claim prepare time: it runs `nvidia-imex-ctl -q --u=<socket path>` chrooted into the driver root and requires a `READY` response before handing out a channel. A claim fails, and is retried, rather than succeeding silently, if the host daemon isn't reachable or ready.\n\nTo enable it:\n\n1. On every participating GPU node, add to `/etc/nvidia-imex/config.cfg`:\n\n   ```text\n   IMEX_CMD_ENABLED=1\n   IMEX_CMD_UNIX_DOMAIN_PATH=/etc/nvidia-imex/imex_ctrl.sock\n   ```\n\n   then restart `nvidia-imex.service` so it creates the socket file (IMEX config changes require a restart to take effect).\n2. `nvidia-imex-ctl` must be present under the driver root alongside `nvidia-smi` (it ships with the `nvidia-imex` package).\n3. If a non-default socket path is used, set `resources.computeDomains.imex.hostSocketPath` (Helm value, plumbed to the kubelet plugin as `IMEX_HOST_SOCKET_PATH`) to match. It defaults to `/etc/nvidia-imex/imex_ctrl.sock`.\n\nAfter installation, follow [Validate host-managed IMEX](guides/compute-domain-workloads.md#validate-host-managed-imex)\nto verify the created objects, channel injection, and Prepare retry behavior.\n\n## Install prerequisites with NVIDIA GPU Operator\n\nThe [NVIDIA GPU Operator](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/latest/index.html) is a Kubernetes operator that automates the deployment and lifecycle management of all NVIDIA software components needed to provision and monitor GPUs in a cluster.\n\nIt can manage the following DRA Driver for NVIDIA GPUs prerequisites for you:\n\n- NVIDIA Driver (v565+ for GPU allocation, v570.158.01+ for ComputeDomains). For clusters where the operator already runs `nvidia-imex` as a host service (for example through systemd), set `resources.computeDomains.imex.mode=hostManaged` to stop the driver from creating per-ComputeDomain `nvidia-imex` DaemonSets. This **inverts** the requirement above: `nvidia-imex.service` must be installed, configured, and left **running** on every participating GPU node. It does not by itself change any behavior. Setting `imex.mode=hostManaged` without this gate enabled is a startup validation error (`helm install`/`helm template` fails immediately, and if bypassed, the controller and kubelet plugin pods will fail to start).\n- `imex.isolation` selects the IMEX isolation strategy, and applies under both `driverManaged` and `hostManaged` mode. It must be set to one of:\n  - `domain` (default) — all workloads running in the same IMEX domain share the same channel (0). Under `driverManaged` mode this is inherent to the model (the driver creates one `nvidia-imex` daemon per ComputeDomain); under `hostManaged` mode, multiple ComputeDomains can still run against the same host IMEX domain, all receiving channel 0, with no isolation between them.\n  - `channel` — intended to eventually give each workload a unique channel within an IMEX domain. Not implemented yet: setting it is a startup validation error regardless of `imex.mode`.\n  - Any other value is a startup validation error.\n- Changing `imex.mode` or `imex.isolation` on a cluster with active ComputeDomain workloads is not supported and is not enforced by the driver, drain and remove existing ComputeDomains first.\n\n#### Host IMEX readiness check (Unix domain socket required)\n\nBecause there is no driver-managed daemon to report readiness under host-managed IMEX, the kubelet plugin validates the host `nvidia-imex` daemon itself at channel claim prepare time: it runs `nvidia-imex-ctl -q --u=<socket path>` chrooted into the driver root and requires a `READY` response before handing out a channel.
