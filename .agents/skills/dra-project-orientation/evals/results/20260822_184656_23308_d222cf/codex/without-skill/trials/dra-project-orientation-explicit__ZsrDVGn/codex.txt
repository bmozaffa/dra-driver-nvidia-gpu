Correspondingly, it contains two DRA kubelet plugins: [gpu-kubelet-plugin](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/tree/main/cmd/gpu-kubelet-plugin), [compute-domain-kubelet-plugin](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/tree/main/cmd/compute-domain-kubelet-plugin). Upon driver installation, each of these two parts can be enabled or disabled separately.\n\nThe two sections below provide a brief overview for each of these two parts of this DRA driver.\n\n### `ComputeDomain`s\n\nAn abstraction for robust and secure Multi-Node NVLink (MNNVL). Officially supported.\n\nAn individual `ComputeDomain` (CD) guarantees MNNVL-reachability between pods that are _in_ the CD, and secure isolation from other pods that are _not in_ the CD.\n\nIn terms of placement, a CD follows the workload. In terms of lifetime, a CD is ephemeral: its lifetime is bound to the lifetime of the consuming workload.\nFor more background on how `ComputeDomain`s facilitate orchestrating MNNVL workloads on Kubernetes (and on NVIDIA GB200 systems in particular), see [this](https://docs.google.com/document/d/1PrdDofsPFVJuZvcv-vtlI9n2eAh-YVf_fRQLIVmDwVY/edit?tab=t.0#heading=h.qkogm924v5so) doc and [this](https://docs.google.com/presentation/d/1Xupr8IZVAjs5bNFKJnYaK0LE7QWETnJjkz6KOfLu87E/edit?pli=1&slide=id.g28ac369118f_0_1647#slide=id.g28ac369118f_0_1647) slide deck.\nFor an outlook and specific plans for improvements, please refer to the [project releases](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/releases).\n\nIf you've heard about IMEX: this DRA driver orchestrates IMEX primitives (daemons, domains, channels) under the hood.\n\n### `GPU`s\n\nThe GPU allocation side of this DRA driver [will enable powerful features](https://docs.google.com/document/d/1BNWqgx_SmZDi-va_V31v3DnuVwYnF2EmN7D-O_fB6Oo) (such as dynamic allocation of MIG devices).\nTo learn about what we're planning to build, please have a look at the [project releases](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/releases).\n\nWhile some GPU allocation features can be tried out, they are not yet officially supported.\nHence, the GPU kubelet plugin is currently disabled by default in the Helm chart installation.\n\nFor exploration and demonstration purposes, see the \"demo\" section below, and also browse the `demo/specs/quickstart` directory in this repository.\n\n## Installation\n\nConfiguration and installation instructions are in the [documentation site](https://dra-driver-nvidia-gpu.sigs.k8s.io/docs/install/) ([source](site/content/docs/install.md)).\n\n## A (kind) demo\n\nBelow, we demonstrate a basic use case: sharing a single GPU across two NVIDIA GPUs delivers two independent Kubernetes DRA plugins:\n\n- `gpu.nvidia.com` - manages allocation of GPUs, including GPU sharing through MIG, Time-Slicing, and MPS, across both bare-metal and sandboxed environments.\n- `compute-domain.nvidia.com` - manages IMEX daemons and allocation of IMEX channel devices required for GPU memory sharing across OS domains on Multi-Node NVLink systems.\n\nBoth are delivered by the Helm chart in [`deployments/helm/dra-driver-nvidia-gpu/`](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/tree/{{< param driver_release_tag >}}/deployments/helm/dra-driver-nvidia-gpu).\n\n## Components\n\n| Binary | Runs as | What it does |\n|---|---|---|\n| `gpu-kubelet-plugin` | DaemonSet, per node | Publishes GPU / MIG / VFIO `ResourceSlice`s and injects CDI on Prepare. |\n| `compute-domain-kubelet-plugin` | Same DaemonSet, per node | Publishes IMEX daemon + channel devices and injects the IMEX mount on Prepare. |\n| `compute-domain-controller` | Cluster Deployment | Watches `ComputeDomain` CRs; spawns a per-CD DaemonSet and the matching `ResourceClaimTemplate`s. |\n| `compute-domain-daemon` | Per-CD DaemonSet, per node | Wraps and supervises `nvidia-imex`; reports peers. |\n| `webhook` | Cluster Deployment | Validates opaque config on `ResourceClaim`s. |\n\n```mermaid\ngraph TB\n    subgraph cluster[\"Cluster-scoped (Deployment)\"]\n        controller[\"compute-domain-controller\"]\n        webhook[\"webhook\"]\n    end\n    subgraph node[\"Each GPU Node (DaemonSet)\"]\n        gpu[\"gpu-kubelet-plugin\"]\n        cdp[\"compute-domain-kubelet-plugin\"]\n    end\n    subgraph percd[\"Per ComputeDomain (DaemonSet)\"]\n        daemon[\"compute-domain-daemon\"]\n    end\n    controller -->|spawns| percd\n    controller -->|creates ResourceClaimTemplates| cdp\n```\n\n## GPU request flow\n\nPod → `ResourceClaim` with a `GpuConfig` / `MigDeviceConfig` / `VfioDeviceConfig` → webhook validates → scheduler binds a device advertised by the GPU plugin → kubelet calls Prepare → plugin writes a CDI spec → runtime injects the GPU into the container.\n\n```mermaid\nsequenceDiagram\n    participant User\n    participant API as Kubernetes API\n    participant Webhook\n    participant Scheduler\n    participant Kubelet\n    participant Plugin as gpu-kubelet-plugin\n    participant Runtime as Container Runtime\n\n    User->>API: Create Pod + ResourceClaim (GpuConfig)\n    API->>Webhook: Validate opaque config\n    Webhook-->>API: Approved\n    API->>Scheduler: Bind device from ResourceSlice\n    Scheduler-->>API: Node + device assigned\n    API->>Kubelet: Start Pod\n    Kubelet->>Plugin: Prepare(ResourceClaim)\n    Plugin-->>Kubelet: CDI spec written\n    Kubelet->>Runtime: Inject GPU via CDI\n    Runtime-->>User: Container running with GPU\n```\n\n## Driver-managed ComputeDomain flow\n\nUser creates a `ComputeDomain` → controller creates a per-CD DaemonSet → each daemon pod runs `nvidia-imex` → daemons publish their IP and clique through `ComputeDomainClique` CRs → workload pods claim a channel from the `compute-domain-default-channel.nvidia.com` DeviceClass → the CD kubelet plugin asserts readiness and injects one or more selected `/dev/nvidia-caps-imex-channels/channelN` devices into the container.\n\n```mermaid\nsequenceDiagram\n    participant User\n    participant API as Kubernetes API\n    participant Controller as compute-domain-controller\n    participant Daemon as compute-domain-daemon\n    participant Plugin as compute-domain-kubelet-plugin\n    participant Runtime as Container Runtime\n\n    User->>API: Create ComputeDomain\n    API->>Controller: Notify (watch)\n    Controller->>API: Spawn per-CD DaemonSet + ResourceClaimTemplates\n    API->>Daemon: Start on each GPU node\n    Daemon->>API: Publish IP + clique via ComputeDomainClique CR\n    User->>API: Create Pod claiming channel\n    API->>Plugin: Prepare(channel ResourceClaim)\n    Plugin-->>API: Assert readiness\n    Plugin->>Runtime: Inject selected IMEX channel devices\n    Runtime-->>User: Container running with NVLink fabric\n```\n\n## Reference\n\nFor opaque config types and CRD definitions: [API reference](../reference/api/)\n\nFor available feature flags and their
